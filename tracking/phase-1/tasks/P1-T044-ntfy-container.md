# P1-T044 · Deploy self-hosted ntfy behind Tailscale with auth

## Goal / expected outcome

An `ntfy` container runs digest-pinned with `auth-default-access: deny-all`, a private topic and a write token for the notifier, reachable only over Tailscale, as the second independent alert channel; iOS push uses ntfy's upstream relay, which carries only a message ID.

- Roadmap: requirements [R1.14](../../../docs/roadmap/phase-1-data-and-monitoring.md#3-requirements) · ToDo [T1.43](../../../docs/roadmap/phase-1-data-and-monitoring.md#4-todo-sets)

## Requirements

- `ntfy` service in Compose with persistent cache/auth DB volumes; served via Caddy on the Tailscale interface (`ntfy.<tailnet>.ts.net`) only
- Auth: deny-all default; user `mt-notifier` (write to topic `mt-alerts-<random>`), user `phone` (read); tokens generated by the bootstrap into the sops file (`NTFY_NOTIFIER_TOKEN`, `NTFY_PHONE_TOKEN`)
- iOS: `upstream-base-url: https://ntfy.sh`, so iOS devices get an APNs wake-up carrying only the message ID (no content); the `ntfy` egress allow-list permits only that relay host
- Cache duration ≥ 24 h so a phone offline overnight still receives queued alerts
- Health check and Prometheus metrics enabled
