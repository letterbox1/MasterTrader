# P0-T022 · Wire sops + age secrets into tmpfs with per-service scoping

## Goal / expected outcome

One sops/age-encrypted secrets file on the workstation (`~/.config/mastertrader/secrets.sops.yaml`, **outside the repo**) is decrypted at stack start into per-service tmpfs files (`/run/secrets/<service>/<name>`), so each container sees only its own secrets, nothing secret is in git, env files or images, and key-age metadata feeds the 90-day rotation alert.

## Requirements

- Repo holds only `infra/secrets/.sops.yaml` (creation rules generated from `infra/secrets/recipients.txt`: host + offline recipients, generated by `just secrets-init` with the identities stored per `secrets.age_identity_store` (default `keychain`); CI uses a test recipient) and `infra/secrets/secrets.example.yaml` (key names, no values). The real file is `~/.config/mastertrader/secrets.sops.yaml` (owner-only 0600; path configurable via `MT_SECRETS_FILE`) with an encrypted copy off-site via restic (P0-T039).
- Layout: top-level key per service (`supabase` (DB passwords, JWT signing keys, `service_role` key; P0-T070), `mt_api`, `litellm`, `llm_local`, `pgbackrest`, `restic`, `worm_seal`, `telegram`, `grafana`, `alertmanager`, `discord`, `data_keys`, `venues`); each leaf has `value`, `created` (date), optional `rotate_days` (default 90 for venue keys, [16 §2.3](../../../docs/16-configuration-and-safety-model.md#23-decisions-approvals-and-hitl); configurable).
- `infra/scripts/secrets-up.sh` (run by `just up`; optionally a systemd user unit `mt-secrets.service` ordered before compose): decrypts with the host identity (from the OS keychain by default), writes each service's leaves to `/run/secrets/<service>/<name>` (tmpfs, 0400, owned by the container uid) and writes `/run/secrets/_meta/key_age.prom` (names + ages, **no values**) for node_exporter's textfile collector.
- Compose mounts only `/run/secrets/<service>` into each service (read-only). Rust services read secrets via `mt_core::config` file sources (P0-T017), Python services via the same file layout, or `*_FILE` conventions for third-party images.
- `worm_owner` is **never** in this file (lint check).
- Grafana alert: any key older than its `rotate_days` (default 90 days; 07 §2, 16 §2.3).

## Verification

### Tests
- Unit: `secrets-lint` fails on a fixture with a `worm_owner` key or an unreferenced secret.
- Integration: the mt-api container sees only `/run/secrets/mt_api`; litellm cannot read the Supabase secrets; the web bundle contains no `service_role` key.
- gitleaks full-history scan: no decrypted file ever committed.

### Scenarios
- Given the workstation reboots, when `just up` (or `mt-secrets.service`) runs, then tmpfs secrets exist before containers start and vanish after `secrets-down` or power off.
- Given the host age identity is unavailable (keychain locked; from P7 the YubiKey removed), when the stack starts, then services fail closed with 'secret missing' and an alert fires.

### Stress / failure injection
- Restart the whole stack 10 times; tmpfs files recreated each time with correct ownership; no secret appears in `docker inspect` env.

## Acceptance criteria

- [ ] No secret in git (gitleaks full-history clean)
- [ ] Each container sees only its own secrets (tested)
- [ ] `key_age.prom` exported without values
- [ ] `docker inspect` of every container shows no secret values in `Env`
- [ ] CI green (clippy, cargo test, ruff, mypy, pytest, `supabase test db`, gitleaks, `pit` check)

## Exceptions & edge cases

- Third-party images that only read env vars: wrap with an entrypoint that reads the file inside the container; never put the value in compose.
- OpenBao migration (07 §2 upgrade path) is out of scope until the signer holds more than one hot key (P5).

## Cardinal rules (do NOT)

- Do NOT commit the decrypted file, an `.env` with values, or the age identity.
- Do NOT add `worm_owner` to the runtime file.
- Do NOT pass secrets as build args or bake them into images.
- Do NOT commit secrets or paste them into chats, issues, PRs or logs; secrets live only in the sops/age file ([07 §2](../../../docs/07-security-notes.md#2-secrets)).
- Pin every image by digest (no `:latest` or floating tags); no telemetry or referral IDs in vendored code.
- Do NOT skip, weaken or delete a test to get CI green.
